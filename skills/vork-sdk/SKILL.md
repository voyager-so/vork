# SDKs (Python and TypeScript)

Scenes are plain dicts/objects with exactly the JSON fields. The SDKs add types, std builders, safe writing and a render wrapper. Everything else (maths, tracks, instance columns) is ordinary code. See `vork help sdk`.

## Start

```sh
vork init my-shot --language python        # scene.py + scene.json + README.md
vork init my-shot --language typescript    # scene.ts + package.json (type: module) + scene.json
```

`scene.json` renders immediately; the source file regenerates it. Edit source, regenerate, render. Existing files are never overwritten.

## Python

Install from the release: `python3 -m pip install "$PREFIX/lib/vork/python"` (source: `pip install ./packages/python`).

```python
from vork import Scene, std, write_scene, render

shape = std("sphere", name="ball", radius=1)          # {buffers, geometry}
scene: Scene = {"version": 2, **shape,
  "nodes": [{"type": "mesh", "geometry": "ball"},
            {"type": "camera", "translation": [3, 2, 5], "target": [0, 0, 0]}]}
write_scene(scene, "ball.json")                        # JSON + buffer sidecar
result = render("ball.json", "still.png", at=0, profile="std/previs")
```

## TypeScript

Package `@voyager-so/vork` (Node 22.18+; install from the archive's `sdk` directory; not implied to be on a registry). Builders: `box`, `sphere`, `cylinder`, `cone`, `torus`, `capsule`, `roundedBox`, `grid`, `revolve`, `extrude`, `text`, plus `sky`, `environmentImage`. TS option keys are camelCase (`sunElevation`, `airDensity`); Python and scene JSON stay snake_case. Example: `packages/ts/examples/orbit.ts`.

```ts
import { sphere, writeScene, render } from "@voyager-so/vork"
// builders: sphere("ball", {radius: 0.5}); pass undefined before required options
await render("shot.json", { out: "still.png", at: 0, profile: "std/previs" })
```

## Key facts

- `std(...)`/builders return `{buffers, geometry}` maps; **merge** them into the scene.
- `write_scene(scene, path, base_dir)` / `writeScene(...)` rebases paths relative to the scene and moves inline buffers >= 4 KiB into a `PATH.buffers.UUID.bin` sidecar written atomically before the JSON. Move the JSON together with referenced files. Writers keep an explicit `$schema` but do not insert one.
- `render()` takes render-time options only (`at`, `profile`, `set`, `channels`); the scene file is unchanged. It prints exposure lines and returns `{exposure: [...], warnings: [{code, requested, dropped}]}`. **Check `warnings`.** An empty list from a 0.1 binary is not proof everything rendered.
- `VORK_BIN` selects the executable (needed to keep 0.1 and 0.2 side by side).
- Types: `vork.types` / TS `Scene`; JSON Schema `sdk/scene.schema.json` in the archive (`packages/ts/scene.schema.json` in source), exported as `@voyager-so/vork/scene.schema.json`.
- Removed in 0.2: `renderArguments` / `render_arguments` (use `render()` or write CLI args yourself), scatter builders (generate instance columns), snake_case option keys in TS `sky`/`environmentImage`, package name `@usevoyager/vork`.
- Validation of ranges and relationships happens in the native renderer, not the SDK: run a cheap render to validate.

## Pattern for code-generated shots

1. One script builds geometry, materials, camera path (compute keys in code), lights.
2. `write_scene` -> `render` a preview profile at 1-2 frames; open the PNG.
3. Parametrize via function arguments; keep seeds explicit for repeatable placement.
4. Commit both the script and the generated JSON only if consumers can't run the SDK.
